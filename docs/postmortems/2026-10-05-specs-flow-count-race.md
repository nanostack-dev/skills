## Summary

The routine extended `echopoint: specs` with a convention-findings branch that creates a second spec. The branch hung off `org-key`, the same parent as `list-empty`, which asserts that a brand-new org has zero specs. When the new spec landed first, `list-empty` read `total=1` and the flow failed; two earlier runs in the CI org had passed because the race went the other way. The branch now starts after `list-empty`, and the fixed flow passed three times in each org. The flow-suite-testing skill now states that a count runs before every write in its scope, and that a branchy flow runs three times before it joins a CI tag.

## Impact

One failed manual run of `echopoint: specs` in the dev org. No scheduled or CI run used the racy definition: it was live for about two and a half minutes, between suite runs.

- **1** failed run (dev org)
- **~2.5 min** racy definition live
- **0** CI or scheduled runs affected

## Trigger

The updated `echopoint: specs` definition, with `lint-create` wired after `org-key`, was saved to the CI org and then mirrored to the dev org.

## Detection

The authoring loop's repeat run in the dev org failed on `list-empty` (`expected=0 actual=1`). The first prod-org and dev-org runs had passed, so the race showed up only on the fourth run.

## Resolution

`lint-create` now starts after `list-empty` in the generator. Both orgs were updated, validated and run three times each, all green.

## Root causes

- **R1** The skill had no rule that a count or empty-list assertion runs before every node that creates in its scope
- **R2** The authoring loop had no repeat-run gate for ordering races before a flow joins a CI tag

## Contributing factors

- The generator updates the tagged flow in place, so the new definition is in the suite as soon as it is saved.

## Lessons learned

### What went well

- The repeat run in the second org caught the race within two minutes, before any scheduled or CI run used it.
- Per-node results named the failing node and its `expected`/`actual`, so the cause was clear without a debug re-run.

### What went wrong

- Two green runs in the first org were taken as proof of the new shape.

### Where we got lucky

- No scheduled or CI suite run started in the roughly two and a half minutes the racy definition was live; a red CI run would have looked like a product regression.
- The race lost on the fourth run; it could have lasted through all of them and reached tomorrow's suites.
